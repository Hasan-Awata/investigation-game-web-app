AI Context & Design Document: Collaborative Investigation Game[01_SYSTEM_OVERVIEW]Application Type: Collaborative, web-based multiplayer detective game.  Backend Stack: Laravel (PHP) utilizing Reverb for WebSockets, Sanctum for Authentication, and an SQLite/PostgreSQL relational database.  Core Loop: Players collaborate in real-time, reviewing evidence and voting on multiple-choice verdicts to progress through sequential case levels.  Progression & Content: System administrators (not players) are responsible for inputting the pre-defined cases into the database. Players earn XP upon solving a case, which unlocks access to advanced cases based on a min_player_XP threshold.  State Management: The GameRooms table strictly tracks the active session via a status enum (active or solved).  [02_USER_ROLES_AND_PERMISSIONS]The system utilizes a room-based multiplayer architecture.  The Host: The user who initializes the session and generates the invite code.  voting_weight = 2.  permissions = The sole user authorized to trigger the "Persona" hint system.  The Participant: Users who join the active session via the invite code.  voting_weight = 1.  permissions = Standard voting and evidence review.  [03_DATA_ARCHITECTURE_AND_ENTITIES]The database relies strictly on a relational schema to prevent data hallucination.  Cases & Levels: Cases contain title, story, min_player_XP, and XP_on_solve. Levels are sequential children ordered by an order_index.  Evidences: Clues linked to a specific Level. Supported types: document, testimony, audio, image, forensic.  Questions & Choices: The puzzle for a Level, structured strictly as a Multiple Choice Question (MCQ). Contains a msg_when_wrong narrative string for hint generation. Choices feature a boolean is_correct flag.  RoomVotes: Transactional table calculating live consensus by tracking user_id, question_id, and choice_id.  [04_GAMEPLAY_LOGIC_FLOW]Level Initialization: Entering a Level provides a subset of Evidences. This compounds with evidence from previous levels.  Voting: Players vote on the Level's Questions, and votes are tallied in real-time using the Host's 2x multiplier.  Batch Submission: Once a consensus is reached for all questions, the submission is evaluated as a single batch. Feedback is obfuscated until submission to maintain tension.  IF (All Consensus Choices == is_correct): Advances the room to the next Level or marks the Case as Solved.  IF (Any Consensus Choice != is_correct): The batch is rejected without revealing which specific question failed.  The Persona: Upon failure, the Host can consult the Persona, which broadcasts the msg_when_wrong string of a failed question to the room as a narrative clue.  [05_UI_UX_VISUAL_DESIGN_SYSTEM]Design Prompt for AI Agent: Generate a UI design for a React.js web application. The aesthetic should be "Modern Digital Forensics" mixed with the atmospheric, immersive UI found in high-end narrative-driven action-adventure games (think holographic interfaces, deep slate greys, and high-contrast analytical overlays). It must avoid looking like a cranky 2000s desktop or a playful children's game. Instead of literal cork and red string (which leans too old-school), use a dark, semi-transparent acrylic workspace (Glassmorphism effect).React Implementation: Utilizes a CSS Grid or a dragging library (like react-beautiful-dnd).Evidence Items: Rendered as modular, card-based components.Documents: Sleek folder icons or minimalist paper thumbnails.Audio: A compact card featuring a glowing audio waveform and a play button.Images: Polaroid-style squares with subtle drop shadows to create depth against the dark background.Interaction: Clicking an item opens a centered, high-resolution modal overlay for deep reading/viewing.Tab 3: The Assessment (Level & Verdict Design)Visual Structure: This is where the core gameplay loop happens.
